## Overview

A test suite that only covers the happy path gives false confidence — it passes today and
still passes after a regression in an edge case nobody tested. This prompt generates a suite
that explicitly covers boundary values and failure modes alongside normal usage.

## The prompt

```md
Generate a unit test suite for this function. Requirements:

1. Cover the normal/happy-path case first.
2. Cover boundary values explicitly: empty input, zero, negative numbers, the smallest
   and largest realistic sizes, and any off-by-one edge implied by the implementation
   (e.g. a final partial chunk, a single-element array).
3. Cover every explicit error/throw path in the function with its own test.
4. Give each test a name that describes the behavior being verified, so a failure is
   understandable from the test name alone without reading the test body.
5. Use one assertion concept per test — don't bundle unrelated checks into one `it`.

Generate the suite now, using the project's existing test framework conventions.
```
