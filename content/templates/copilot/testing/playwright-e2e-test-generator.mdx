## Overview

The fastest way to end up with a flaky e2e suite is CSS-selector locators and manual
`waitForTimeout` calls. This prompt generates tests that use Playwright's role-based locators
and auto-waiting assertions from the start, which are both more readable and more resilient to
markup changes.

## The prompt

```md
Write a Playwright test for the user flow I describe. Requirements:

1. Use `getByRole`, `getByLabel`, or `getByText` for every locator. Only fall back to
   `data-testid` if there's truly no accessible way to target the element, and say so
   explicitly when you do.
2. Never use `page.waitForTimeout`. Rely on Playwright's built-in auto-waiting via
   `expect(locator).toBeVisible()` / `.toHaveText()` etc.
3. Assert on what the user would actually see (visible text, ARIA state), not
   implementation details like class names or DOM structure.
4. Keep each test focused on one flow; split unrelated assertions into separate tests.

Describe the flow now, and I'll generate the test.
```
