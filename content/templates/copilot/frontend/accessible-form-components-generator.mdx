      function EmailField({ error, ...props }: { error?: string } & React.ComponentProps<'input'>) {
        const id = useId()
        const errorId = `${id}-error`
        return (
          <div>
            <label htmlFor={id}>Email</label>
            <input
              id={id}
              type="email"
              aria-required="true"
              aria-invalid={!!error}
              aria-describedby={error ? errorId : undefined}
              {...props}
            />
            {error && <p id={errorId} role="alert">{error}</p>}
          </div>
        )
      }

## Overview

Forms are one of the highest-impact places to get accessibility right — they're the primary
way users provide input, and the most common place `label`/`input` association and error
announcement get skipped under deadline pressure. This prompt bakes the correct pattern in
from the first draft.

## The prompt

```md
Generate a React form field component with these requirements, non-negotiable:

1. Every input has a visible `<label>` associated via `htmlFor`/`id` — never rely on
   `placeholder` or `aria-label` alone as the only label.
2. Required fields set `aria-required="true"` and show a visible indicator (not color alone).
3. Validation errors are associated via `aria-describedby` pointing at an element with
   `role="alert"`, and the input sets `aria-invalid="true"` while an error is present.
4. All interactive elements are reachable and operable via keyboard alone — no
   click-only handlers on non-interactive elements.

Generate the component now for the field type I specify, following this pattern exactly.
```
