## Overview

Query performance problems are cheap to fix in review and expensive to fix in production once
a table has grown. This rule catches the three patterns that account for most real-world
slow-query incidents: N+1 loops, unbounded result sets, and missing indexes on hot paths.

## The prompt

```md
Review this database query code for performance issues:

1. Flag any query issued inside a loop over another query's results (N+1 pattern).
   Recommend the batched/`include`-based alternative.
2. Flag any query with no `LIMIT` (or ORM equivalent) that could return an unbounded
   number of rows as the table grows. Recommend pagination.
3. For any `WHERE`, `JOIN`, or `ORDER BY` clause on a column, ask whether that column
   is indexed; if you can't tell from the code alone, say so explicitly rather than
   assuming either way.
4. Flag any `SELECT *` where only a few columns are actually used downstream.

List findings in order of likely production impact, most severe first.
```
