## Overview

This rule teaches Cursor (or any tool that reads project-level rule files) to catch the most
common App Router mistakes during code review: components marked `"use client"` that don't
need to be, data fetched client-side when it could happen on the server, and missing
`loading.tsx`/`error.tsx` boundaries for routes that stream.

## The prompt

```md
You are reviewing a Next.js App Router change. For every file under `app/`:

1. Flag any `"use client"` directive on a component that does not use state, effects,
   browser-only APIs, or event handlers. Explain what to remove and why the component
   can be a Server Component instead.
2. Flag any `useEffect` + `fetch` pattern that could instead be an `await` inside a
   Server Component, passing the result down as a prop.
3. Confirm every route segment with an async Server Component has a sibling
   `loading.tsx`; if missing, suggest adding one.
4. Confirm `params` and `searchParams` are awaited (they are Promises), not destructured
   synchronously.

Report findings as a bullet list grouped by file, most severe first. Do not rewrite the
code unless asked — describe the fix.
```
